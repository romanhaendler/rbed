# 07: The restore guarantee at scale

**What to build:** Evidence that a restore never differs, across everything the library can express. The generator from ticket 02 runs thousands of random Rule sets and inputs from every construct; for each, Snapshots are taken at every moment and at random moments, chains of restores (after every single moment) run to the end, and every round trip is byte-identical. A final teeth audit lists every piece of state the Snapshot writes and shows a failing test for each when omitted or corrupted. Snapshot size stays bounded by the Retention Limit; Snapshot time and size are noted for the performance tests' realistic Rule set. See spec: Testing Decisions "Differential testing of the guarantee", "Snapshot contract tests", "Performance".

**Blocked by:** 04, 05, 06

**Status:** done

- [x] Random cases (regular build: thousands with fixed seeds; extended profile: far more with fresh seeds) never differ between the uninterrupted run and runs with one Snapshot at every moment, with Snapshots at random moments, and with a restore after every single moment
- [x] Every Snapshot of a restored Detector is byte-for-byte identical to the one it was restored from, over all generated cases
- [x] The extended profile has been run locally with a large number of fresh seeds without a difference (count and duration recorded in Comments)
- [x] Teeth audit: a list in the Comments of every piece of state the Snapshot writes, each with the test that fails when it is omitted or corrupted; no piece without one
- [x] Snapshot size is bounded by the Retention Limit (test with windows at the limit); Snapshot time and size for the realistic Rule set are recorded
- [x] Pushing a Sample still allocates nothing more than before (existing allocation checks)
- [x] Every regression found on the way is a named JUnit case
- [x] `mvn -q verify` passes

## Comments

- New: `SnapshotGuaranteeTest` (4 generated-case tests + the size test), `SnapshotValidationTest`, `Differential.compareWithSnapshots(config, restoreConfig, watched, ops, Mode, rng, p)` (A is an uninterrupted fresh Detector; B takes a Snapshot at every moment, or each moment with probability p, checks that two Snapshots in a row are equal and, in mode RESTORE, continues as a restore of its own Snapshot, whose own Snapshot must equal the one it came from byte for byte). `Run.restoreFrom`; `Run.stateLines()` now includes `replayPoint`. - Regular build (3000 fixed seeds each, about 20 s in all): a twin restored at every moment and run to the end; Snapshots at every moment and at random moments (p=0.3) of an otherwise uninterrupted Detector; a chain of restores after every single moment (also before the first op, after `close()` and after a rejected push); restores at random moments (p=0.25).
